# Analiza bezpieczeństwa — runda S007 (2026-11-22)

**Zakres:**
- aplikacja `macos/` (SwiftUI), polecenia JSON CLI, `vault.Peek`, skrypt budowania;
- regresje względem S001–S005;
- zgłoszenia właściciela z testów na pendrive'ach (literówka w `--card`, `sudo`, wolny zapis).

## Wynik

Dwie luki poprawione w tej rundzie (R7-01, R7-03). Jedna wysoka została przeniesiona do osobnej specyfikacji S006 (R7-02). Format udziałów bez zmian; brak regresji S004 i S005: `go test -race ./...` jest zielony.

## Sprawdzone bez znalezisk

- **Bez powłoki (G4):** kod Swift uruchamia wyłącznie `Process` z tablicą argumentów. Test przeszukuje źródła pod kątem `/bin/sh`, `bash`, `zsh` i `-c`.
- **UI nie dotyka udziałów (G5):** kod Swift nie czyta katalogów sejfów. Stan pochodzi z JSON CLI, a jawna treść nigdy nie przechodzi przez aplikację.
- **Log montowania (CG-12):** zawiera komunikaty CLI (nazwa sejfu, punkt montowania, ostrzeżenia), bez nazw plików. Katalog ma prawa 0700, plik 0600.
- **Zapis na nośniki (S004 §7):** każdy zapis na nośnik wymaga wyboru użytkownika w arkuszu (kreator, backup, odtworzenie). Aplikacja niczego nie tworzy automatycznie.
- **JSON:** `volumes` ujawnia tylko nazwy i identyfikatory sejfów z nagłówków (jak F-05), bez nazw plików.

## Stan wcześniejszych znalezisk

Bez zmian względem rundy S004: R4-03 otwarte i złagodzone, F-03–F-08 jak wcześniej. Nowe obserwacje, poza bezpieczeństwem:
- zapis przez sejf na wolnym pendrivie USB 2.0 był ~4× wolniejszy niż zapis bezpośredni (0,8 vs 3,7 MB/s);
- kandydat na osobną specyfikację wydajności.
