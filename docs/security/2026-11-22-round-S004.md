# Security analysis — round S004 (2026-11-22)

Scope: S004 (snapshots, backup to a spare card, recovery, masks from `SecRandomCopyBytes`, mounting via macFUSE/FSKit) and regressions against S001–S003. Reviewed the code (`internal/split`, `internal/vault`, `internal/fusefs`, `internal/fusemount`, `cmd/xordock`), the tests and E2E on hardware: SSD with FileVault, HFS+ SD card, disk images as the spare card and the new working card.

## Result

Two gaps were fixed in this round (S005). One medium finding (R4-03) remains open with mitigation; it does not affect confidentiality. F-01 and F-02 from round S001 are closed. No open critical regressions.

| ID | Severity | Finding | Status |
|---|---|---|---|
| R4-01 | high | `backup prune` deleted older points after merely reading the newest point's index. A corrupted block of the newest point would mean losing the only good copy (B-04). | **fixed** in S005, test `TestPruneRefusesIncompleteNewest` |
| R4-02 | medium | The index read from the shares was not validated. A path with `..` in a corrupted or substituted share would lead `export` outside the target directory. | **fixed** in S005, test `TestIndexPathsValidated` |
| R4-03 | medium | The FSKit backend (macFUSE 5.5 on macOS 27) does not report an error from `close(2)` to the application and has no separate per-file `fsync` call. When the commit on close fails (e.g. the card is removed at that moment), the application may consider the write successful. | **open, mitigated**: a failed commit switches the vault into the error state, further operations return EIO, the volume is unmounted, and the CLI reports an emergency unmount. The last committed version is not lost (T-04, `TestCrashAtEveryStage`). To do: a compatibility test of which FSKit calls are delivered for `fsync(2)` (CP-09). |
| R4-04 | low | libfuse starts the mount helper via `fork` from a multithreaded process (Go): warning "forking a threaded process is unsafe". The risk concerns availability (child hang), not confidentiality. | **accepted**; 6 mounts in E2E without problems. |
| R4-05 | low | Full blocks written ahead (spill) for an uncommitted file and blocks overwritten after spill remain as orphaned objects until the next open (GC). They are valid XOR shares without plaintext, so they only cost space. | **accepted** |
| R4-06 | low | Snapshots extend the life of old shares: the working card holds the masks of all pinned versions. A lost working card together with the SSD also exposes the history. | **documented** (A+B outside the model). After recovery the CLI recommends deleting the old A (`docs/recovery.md`). |
| R4-07 | low | `chmod`/`chown` accepted with no effect (S004 A-06). Modes are always 0600/0700, i.e. restrictive. | **accepted** |
| R4-08 | informational | The mount point `/Volumes/xordock-<name>` and the spare card header reveal the vault name (like F-05). | **accepted** (D-04, R-06 from S001) |

## Checked with no findings

- **Masks (D-06, CG-02):** `SecRandomCopyBytes` with the result code checked; an error stops the write (`TestMaskErrorStopsSplit`). The TEST_ONLY source exists only in `_test.go`, so `go build` does not include it.
- **Recovery (R-02, CG-09):** the point view reassembles only objects from its index. The spare card will not open as a working card (`ErrSpareCard`), and a working card will not be accepted as a spare.
- **Backup (B-03, B-04):** only adds files (tmp + rename) and never overwrites or deletes. Space is checked before any change. The READY point is created after both sides are persisted and verified, and the snapshot is pinned before copying.
- **GC (S-04):** when a snapshot index is unreadable, GC is paused (`TestGCStopsWhenSnapshotUnreadable`).
- **FUSE adapter:** contains no cryptography. Plaintext lives only in RAM buffers, wiped on close and after card loss (`TestCardRemovedIsDeterministicError`). The cgo bridge does not retain C pointers.
- **Logs (CG-12):** the adapter logs nothing. Mounting logs the vault identifier and root paths, without file names.
- **File permissions:** shares, headers and points have 0600, directories 0700.
