# Security analysis — round S001 (2026-11-22)

Scope: S001, the only spec so far. Reviewed the code (`internal/split`, `internal/vault`, `internal/davfs`, `internal/mount`, `cmd/xordock`), the tests and behavior on real hardware (SSD with FileVault + HFS+ SD card). Searched for regressions and gaps against FR-01–FR-27, G-06 and the adversary model from §5.7.

## Result

No unclosed critical regressions (CG-11 ✅). One high finding (F-01) blocks a production release; its resolution is S002.

| ID | Severity | Finding | Status |
|---|---|---|---|
| F-01 | high | The macOS WebDAV agent (`webdavfs_agent`) caches the contents of opened files in `/private/tmp/.webdavcache.<pid>.*` on the internal SSD (files deleted but still open). Plaintext therefore lands on the SSD outside share A, contrary to the intent of FR-24. Confirmed with `lsof` during E2E. | **open** → S002. Mitigation: `mount` refuses to run without FileVault (data at rest encrypted), described in `docs/usage.md`. |
| F-02 | medium | The access token is in the mount URL, visible in `mount` to all local accounts. Another local user (or process) who knows the token can read and write the vault via 127.0.0.1. | **accepted for the prototype** (the §5.7 model assumes the adversary does not control the computer). Mitigation: random 128-bit token, `Host` check and rejection of `Origin` (DNS rebinding, browsers), test `TestHandlerGuards`. To be resolved in S002 (integration without a TCP socket). |
| F-03 | medium | XOR malleability: anyone who can modify share A and recompute its checksum can predictably flip bits of the plaintext; SHA-256 checksums will not detect it. | **accepted** (R-04, decision Q-05 in S001 §9.8). A separate integrity spec. |
| F-04 | low | Deleting old shares is a plain `unlink`. Old masks (B shares) may be recoverable from the card with forensic tools; together with an old copy of A (e.g. from Time Machine) they reconstruct old versions. | **documented**: the §5.7 model assumes the adversary does not have B. Recommendation in `docs/usage.md`: overwrite a card taken out of service entirely or destroy it. |
| F-05 | low | Plaintext metadata: vault name (header, path on the card), number and sizes of objects, write times. The index size approximates the number of files. | **accepted** (R-06). File and directory names are in the XOR-split index, i.e. they are not stored in plaintext on any medium (test CG-02/03 also searches for the name). |
| F-06 | low | Copies of plaintext in RAM: the Go GC may move buffers, so `split.Wipe` works on a "best effort" basis. Swap on Apple Silicon is encrypted. | **accepted** (out of scope: attacker on an unlocked Mac). |
| F-07 | low | A handle opened long ago may refer to blocks deleted by GC after two subsequent commits; the read ends with an error, not with wrong data. | **accepted**, consistent with FR-14. |
| F-08 | low | `init` does not take the vault lock. Concurrent `init` and `mount` of the same vault are not possible in practice (`init` refuses when a superblock exists). | **accepted**. |

## Checked with no findings

- **Mask reuse (FR-07, FR-08, FR-21):** every object has a new random identifier and a new mask; objects are immutable. Instrumented test.
- **Cross-share hashes:** none exist (decision Q-05); a checksum covers only its own share.
- **Logs (FR-15, CG-09):** only object identifiers, commit numbers, A/B root paths and errors without user file paths (`stripPaths`) are logged. No logging of content or masks.
- **Mixing up shares (FR-14, FR-17):** the share header binds the magic, side, vault and object identifiers and the length; any mismatch is an error.
- **Consistency (FR-09, FR-10, G-05):** objects persisted (fsync + F_FULLFSYNC barrier) before the superblocks; superblock A, then B; deterministic recovery (complete or roll back), other states are an explicit error.
- **Card loss (FR-18, SC-02):** the error state blocks further commits; the mount is force-unmounted within ≤ 1 s.
- **Two processes on a vault:** `flock` (`TestSecondOpenLocked`).
- **Export:** paths from the index are normalized (`path.Clean`), so they do not escape the target directory; export refuses to write into an existing directory and warns about the loss of protection.
- **Dependencies (E1):** one, `golang.org/x/net` v0.63.0 (official Go module).
- **File permissions:** shares, headers and the mount point with `0700`/`0600`.
